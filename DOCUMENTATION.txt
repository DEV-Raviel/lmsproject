e-GURO LEARNING MANAGEMENT SYSTEM
================================

OVERVIEW
--------
e-GURO LMS is a PHP and MySQL/MariaDB web application for managing classes,
learning materials, assignments, quizzes, and student submissions. It provides
role-specific dashboards for administrators, teachers, and students, using a
shared navigation style with role-specific tools.

REQUIREMENTS
------------
- Apache with PHP 8.1 or later (developed and checked with PHP 8.2)
- MySQL 5.7+ or MariaDB 10.3+
- PHP PDO and the PDO MySQL driver (pdo_mysql)
- PHP Fileinfo extension for validating uploaded files
- A modern web browser

No Composer or npm packages are required to run the application.

LOCAL INSTALLATION (XAMPP)
--------------------------
1. Copy the LMS folder into the web server document root, for example:
       /opt/lampp/htdocs/LMS
2. Start Apache and MySQL from the XAMPP control panel.
3. Create/import the database:
   - Open phpMyAdmin, select the Import tab, and import database/schema.sql.
   - The schema creates and selects the lms_db database.
4. Configure the database. The application reads `LMS_DB_HOST`,
   `LMS_DB_NAME`, `LMS_DB_USER`, and `LMS_DB_PASSWORD` from the process
   environment. If unset, local XAMPP defaults are:
       Host: localhost
       Database: lms_db
       User: root
       Password: (blank)
   Set the environment variables for installations using different
   credentials; database errors are logged server-side and are not displayed
   to users.
5. Open the application:
       http://localhost/LMS/
6. Sign in with a seeded account listed under DEMO ACCOUNTS below.

If the database already contains LMS data, back it up before importing or
changing its schema. Importing the seed schema is intended for initial setup;
it is not a substitute for a production backup or migration plan.

USER ROLES AND COMMON WORKFLOWS
-------------------------------
Sign-in and security
  - Sign in using the account email or user code and password.
  - After five failed attempts within 15 minutes, that account identifier and
    source IP are temporarily blocked for 15 minutes.
  - Sign-in uses a per-session CSRF token. Sessions use strict cookie-only
    mode, HttpOnly, SameSite=Lax, and Secure cookies when HTTPS is enabled.
  - There is no persistent "Remember me" feature. The legacy reset.php route
    is disabled; request a temporary password from an Administrator if needed.

Administrator
  - Use User Management to create and manage accounts, classes, and enrollments.
  - Use Filters to search accounts by name, code, email, or role and classes by
    code, subject, teacher, semester, or academic year.
  - Search the Student Profiles list by student name, user code, or email.
  - New accounts receive a random temporary password shown to the Administrator
    once. The user must change it before opening any role pages.
  - Enroll multiple students into a class by pasting up to 200 student user
    codes or email addresses into the class enrollment panel. Duplicate
    enrollments are skipped and unmatched entries are reported.
  - Use Account Recovery to assign a random temporary password to another
    account. It is shown once to the Administrator; the user must change it
    before accessing the LMS.

Dean
  - Manage school announcements; published updates appear on teacher and
    student dashboards, while drafts remain private to the Dean.
  - Use School Events to create global events visible to every role. Teachers
    and students can view these events but cannot edit them.
  - Add private personal tasks to the Dean calendar; due dates appear alongside
    school events, and tasks can be edited, completed, reopened, or deleted.

Teacher
  - Open the dashboard to review assigned classes and activity.
  - Open My Classes to see each assigned class and jump to its students,
    assignments, quizzes, or learning materials. Class links keep the selected
    class active in the related teacher tools.
  - Use Students to view students enrolled in one class or across all assigned
    classes.
  - Use Filters on the student, assignment, quiz, learning-material, and
    gradebook lists to narrow results by class or relevant text.
  - Use Academic Calendar to view class deadlines, teacher-only events, and
    school-wide events. School-wide events are read-only.
  - Add private personal tasks on the calendar to track teaching work. Due
    dates appear alongside class deadlines and can be edited or completed.
  - Expand the event count on a busy calendar day to view the remaining events.
  - Use Assignments to create class work with instructions, deadlines, and an
    point value, and an optional attachment.
  - Open Gradebook to download student submissions and score each assignment.
    Scores must be between zero and the assignment's points possible.
  - Use Learning Materials to upload and share class resources.
  - Use Quiz Builder to create a quiz with multiple-choice and short-answer
    questions, answer keys, points, a deadline, and an optional time limit.
  - Use Calendar, Profile, and Settings for the other teacher pages.

Student
  - Open My Classes to view enrolled classes and class details.
  - Open Student Profile to view enrollment information submitted through the
    school's enrollment form. Only the signed-in student and Administrators
    can view this profile; students cannot edit it.
  - Use Calendar to review class assignment and quiz deadlines, student-only
    events, and read-only school-wide events.
  - Add private study or reminder tasks from the calendar and track them by
    due date alongside class deadlines.
  - Review published school announcements on the dashboard.
  - Open Lessons to download materials shared by a teacher.
  - Use To Do, Tasks, and Quizzes to review upcoming or due work.
  - Submit assignment files before the deadline.
  - Open an available quiz, complete it, and submit it. Multiple-choice and
    short-answer questions are graded automatically against the teacher's
    answer key.
  - Open Grade Report to view assignment scores, quiz scores, due dates, and
    submission status for enrolled classes.
  - Use Filters on To Do, Tasks, Quizzes, Lessons, and Grade Report to find work
    by title, class, teacher, or status.

Teacher and student pages share the same overall visual style, but the
available data, actions, and dashboard labels depend on the signed-in role.
Unauthenticated users must sign in. Dean pages require the Dean role and
Administrator pages require the Administrator role; neither role can open the
other role's protected tools.

Navigation
  - On screens 1024 pixels wide or narrower, use Menu to open the role-specific
    navigation drawer. Close it with the backdrop, Escape, or a navigation link.
  - On larger screens, the same grouped navigation remains in the left sidebar.
  - The account menu in the top bar contains the profile link and sign-out.
  - Data tables can be scrolled horizontally on narrow screens without
    widening the page.

DATABASE AND MIGRATIONS
-----------------------
For a new installation, use database/schema.sql. It contains the complete
current schema, including quiz tables and demo seed data.

The files in database/migrations are for upgrading an existing database:
  1. database/migrations/2026_11_auth_security.sql
  2. database/migrations/2026_11_forced_password_change.sql
  3. database/migrations/2026_11_create_quizzes.sql
  4. database/migrations/2026_11_quiz_attempt_timing.sql
  5. database/migrations/2026_11_create_calendar_events.sql
  6. database/migrations/2026_11_dean_announcements_and_account_recovery.sql
  7. database/migrations/2026_11_personal_calendar_tasks.sql
  8. database/migrations/2026_11_student_profiles.sql
  9. database/migrations/2026_11_assignment_grading.sql

Apply the auth-security migration to existing installations before using the
login throttling feature. Login attempts are limited per normalized account
identifier and source IP; five unsuccessful attempts within 15 minutes lock
both buckets for 15 minutes. The migration is safe to apply more than once.
Apply the forced-password-change migration once to existing installations
before creating accounts or resetting passwords with the temporary-password
workflow.
Apply the quiz table migration before the timing
migration; the timing migration alters quiz_attempts and is not intended to be
run repeatedly. Apply the calendar events migration, then the Dean/recovery
migration (which converts existing Admin/Dean events to school-wide events and
creates announcement and one-time reset-token tables). Apply personal calendar
tasks after the Dean/recovery migration, and student profiles independently.
Back up the database before applying migrations and verify that each target
change has not already been applied.
The assignment-grading migration adds the points-possible field used by the
teacher Gradebook and must be applied before creating or grading assignments.
Administrator deletion is blocked when an account or class is linked to graded
student work; those records cannot be deleted without removing academic history.

STUDENT ENROLLMENT PROFILES
---------------------------
Administrators can open Student Profiles from the Admin navigation to edit a
student's enrollment information or import a Google Forms response CSV. To
export a CSV, open the form's Responses spreadsheet in Google Sheets and use
File > Download > Comma-separated values (.csv).

The CSV must include a Student ID, Student Email, or CCC Email column that
matches an existing student account. Recognized enrollment question headers
are mapped to the profile fields. Rows with missing or conflicting account
identifiers, duplicate students, invalid dates, invalid GWA values, or other
invalid answers are reported; the import is all-or-nothing. Blank imported
answers clear that field, while columns not included in the CSV leave existing
profile data unchanged. The importer accepts files up to 5 MB and 5,000 rows.
Student ID and account email are used only for matching and are not changed by
the import.

ACCESSIBILITY AND NOTIFICATIONS
-------------------------------
Authenticated pages include a skip-to-content link, keyboard focus indicators,
current-page navigation state, and shared accessible toast notifications for
status and error messages. Notifications remain readable inline if JavaScript
is unavailable. On narrow screens, class tabs can be scrolled horizontally.

FILE UPLOADS
------------
Teacher assignment attachments and learning materials, and student assignment
submissions, are saved under uploads/. The application limits uploads to 10 MB
and checks the file extension and detected MIME type. Supported formats include
PDF, Office documents, images (PNG/JPG), and ZIP files.

The Apache/PHP process must be able to create and write files in the relevant
uploads subdirectories. Grant write access to the web-server account for only
the required upload folders; do not make the entire project world-writable.
Ensure the PHP upload_max_filesize and post_max_size settings are compatible
with the application's 10 MB limit. Restart Apache after changing php.ini.

IMPORTANT SECURITY AND DEPLOYMENT NOTES
---------------------------------------
- The included database settings and seeded accounts are for local development.
  Use a dedicated database account with a strong password in a deployed system.
- Change or remove all demo accounts and passwords before deployment.
- Serve the application over HTTPS and configure secure PHP session cookies.
- Restrict database and filesystem permissions to the minimum required.
- Back up the database and uploaded files regularly.
- Review PHP/Apache upload limits and error logging for the deployment.
- Do not expose development tools, database administration pages, or detailed
  error output to the public internet.

TROUBLESHOOTING
---------------
Database connection failed
  - Confirm MySQL is running and the database exists.
  - Check LMS_DB_HOST, LMS_DB_NAME, LMS_DB_USER, and LMS_DB_PASSWORD in the
    Apache/PHP process environment (or use the documented local defaults).
  - Confirm PHP has pdo_mysql enabled.

Login does not work
  - Confirm the account exists and the user ID/email is entered correctly.
  - For a fresh demo installation, use the seeded password shown above.
  - Confirm the account's role is correct in the users table.
  - If sign-in attempts were throttled, wait 15 minutes before trying again.
  - Reload the sign-in page if its CSRF token has expired.

Upload fails
  - Confirm the upload folder exists and is writable by Apache/PHP.
  - Use a supported file type and a file no larger than 10 MB.
  - Check upload_max_filesize, post_max_size, and the PHP/Apache error logs.
  - Ensure Apache permits the uploads/.htaccess rules so directory listings
    and executable script extensions are denied.

Quiz tables are missing
  - For a new database, import database/schema.sql.
  - For an existing database without quiz tables, back it up and apply the two
    migration scripts in the order listed in DATABASE AND MIGRATIONS.

Announcements or account recovery are unavailable
  - For a new database, import the updated database/schema.sql.
  - For an existing database, back it up and apply
    database/migrations/2026_11_dean_announcements_and_account_recovery.sql
    after the calendar events migration.
  - Account recovery links are shown to an Administrator only once and expire
    after 30 minutes; copy the link and share it directly with the account
    owner.

Personal calendar tasks are unavailable
  - For a new database, import the updated database/schema.sql.
  - For an existing database, back it up and apply
    database/migrations/2026_11_personal_calendar_tasks.sql after the Dean and
    account recovery migration.

Student profile is empty or unavailable
  - For a new database, import database/schema.sql.
  - For an existing database, back it up and apply
    database/migrations/2026_11_student_profiles.sql once.
  - Confirm the account has the student role and match the CSV using the
    student's existing user code or account email.

Teacher has no classes or a student sees no class work
  - Confirm the teacher is assigned to the class in the classes table.
  - Confirm the student is enrolled in that class in class_enrollments.
  - Confirm the assignment or quiz belongs to that class and is not past due.

SUPPORT AND MAINTENANCE
-----------------------
Before changing the application or its database, make a backup of the source,
database, and uploads folder. Test schema changes and role-specific workflows
in a non-production environment before deploying them.
